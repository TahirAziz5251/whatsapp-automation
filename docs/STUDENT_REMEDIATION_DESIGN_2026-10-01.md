# Student-first remediation design

Scope authorized by user: Groq token budget, duplicate executions, and accurate database retrieval; student-assistant first. Audit phase has ended. Broader missing memory/KB/Calendar/CRM integrations remain separately documented.

1. Preserve active workflow ID, node IDs, credentials, webhook path, and inactive copies. Save consistent n8n snapshot, workflow export, compose copies, encrypted runtime configuration, and all six native PostgreSQL databases before mutation.
2. Keep global Evolution webhook and clear the duplicate student instance webhook through the supported connect/settings endpoint, preserving MESSAGE subscription. This avoids restarting the connected WhatsApp session. Do not connect disconnected instances during this phase.
3. Normalize actual Info.ID, device-qualified JIDs and instance identity. Reject missing identity instead of generating random dedup IDs or silently selecting another tenant. Use Redis SET NX EX with an instance/message key before LLM/tool work. Retried webhook transport must not repeat AI processing.
4. Select Groq openai/gpt-oss-120b (available with the active credential; supported successor), with maxTokensToSample=512, temperature=0.1, short instructions, two memory turns and at most three agent iterations. The old maxTokens field is not supported by this node. Model switching alone does not increase the account's 8000 TPM quota; keep usage bounded and test provider responses.
5. Replace seeded BISE answers with parameterized native PostgreSQL queries under gateway_readonly, read-only transaction/session, connection and statement timeouts, explicit NOT_FOUND/INVALID_INPUT/DB_UNAVAILABLE statuses, and guaranteed client cleanup. Return declared exam identity and subject marks; never return CNIC or full student phone. POS/hospital data-query paths can use the same verified database gateway while delivery remains blocked by disconnected instances.
6. Use require('pg') and require('ioredis') from installed modules, permitting only these modules in n8n. Preserve existing data volumes on service recreation. Check container-to-host PostgreSQL/Groq/Evolution connectivity before publishing.
7. Test argument decoding in the installed ToolCode runtime; known and unknown roll numbers, malformed input, subject retrieval, disconnected DB failure, duplicate IDs, same IDs across distinct instances and wrong-tenant operations. Compare actual query results to an independent read-only SQL baseline.
8. Publish using supported n8n CLI and restart only the n8n service if no existing API key is available. Verify the actual active version and registered webhook after deployment. Preserve rollback files and commands.
9. Tell the user when ready, then observe their query from a second WhatsApp account. Record message ID, exactly one inbound execution, actual tool output, final answer and Evolution send acknowledgement. Delivery acknowledgement is distinct from a human read receipt. Until that evidence exists, live E2E is PENDING, not PASS.

Rollback: restore the saved active-workflow export via n8n import, publish the same ID and restart; restore the original student webhook through the same API; restore compose if module configuration was changed. Database dumps are recovery backups, not required for normal rollback because business data is not mutated by read-only retrieval fixes.
